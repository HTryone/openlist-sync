# 为什么是 OpenListSync

把几个本地文件夹"放进网盘"，大多数人的做法是装一个网盘客户端——然后发现：

- 客户端只管它自己那一个网盘，换一家就得再装一个
- 想备份的是**工作文件夹**，却被迫把文件搬进客户端指定的"同步目录"
- 同步规则黑盒：哪些传了、哪些被排除、删除去了哪，全都说不清
- 多台机器/多个 Agent 协作时，删除传播要么不做（垃圾越堆越多），要么做得很危险（误删连本地也删）

OpenListSync 的答案是：**你自己定义"哪个本地文件夹 ↔ 网盘哪个目录"，剩下的交给一个透明的同步引擎，并且每一行为都可验证。**

## 核心设计

### 1. 本地优先，网盘只是远端副本
所有程序、Agent、你自己——读写**永远走本地路径**，毫秒级，不依赖网络。网盘是后台定期同步的**异地副本**。断网照样干活，联网后自动补同步。

### 2. 目录映射一目了然
```
本地 D:\项目\甲方   →   网盘 agents-sy/甲方
本地 D:\项目\乙方   →   网盘 agents-sy/乙方
```
一个本地文件夹 = 网盘一个同名子目录。在面板里选文件夹就自动配好，没有隐藏规则。

### 3. 删除是安全的，且有后悔药
本地删除 → 网盘同步删除，但被删文件**归档到 `agents-sy/.trash/<文件夹名>/`**（每个文件夹独立归档，不会被二次清理）。误删了？去 `.trash` 拿回来。

### 4. `.nosy`：你说了算的过滤规则
每个同步文件夹根目录放一个 `.nosy`，写法就是你熟悉的 **gitignore**：

```
node_modules/        # 依赖不同步
build/  dist/        # 构建产物不同步
.env                 # 密钥文件绝不进网盘
docs/*
!docs/README.md      # 排除整个目录，但留一个例外
```

排除规则、白名单、任意层级匹配——全部可预测、可审查。

### 5. 挂载：网盘当一个本地磁盘用
点一下「挂载」，整个网盘变成 `Z:` 盘。资源管理器直接浏览、播放器直接放视频。
配合**预取缓存**（32MB 分块 + 16 并发流 + 512MB 预读），实测：

- 文件夹浏览：毫秒级
- 视频起播 / 拖动进度条：**0.1 秒**（缓存命中）
- 缓存自动清理：按保留时长 + 容量上限双规则回收，磁盘不会越吃越多

### 6. 像一个正常的 Windows 软件
- 双击启动 → 右下角托盘，**没有黑色命令行窗口**
- 单实例：重复双击只会打开面板
- 退出 = 托盘右键「退出」，挂载自动卸载、不留死链
- 分发就一个文件夹（exe + 自带 rclone），复制给同事就能用

## 适用场景

| 场景 | 怎么用 |
|---|---|
| **个人/团队文件备份** | 多个本地文件夹 → 网盘，每 30 分钟自动双向 |
| **多机/多 Agent 协作** | A 机上传 → B 机拉取；显式「从网盘拉取」按钮，只增不删 |
| **网盘当临时工作盘** | 挂载成 Z: 盘，直接改网盘上的文件 |
| **看电影/听歌** | 挂载 + 播放模式，网盘里的媒体直接在线播放 |
| **排除敏感/垃圾文件** | `.nosy` 写清楚，密钥和构建产物永远不进网盘 |

## 不适合什么

诚实地说，它**不是**这些工具的替代品：

- **需要版本历史/回滚**（每个快照都可恢复）→ 用 restic/Kopia
- **需要多人实时协作编辑** → 用坚果云/OneDrive 这类
- **需要增量级同步超大仓库**（几十万文件）→ 用 Git

它的定位是：**一台 Windows 电脑 ↔ 一个 OpenList（WebDAV）之间的、透明可控的定时双向同步**。这件事，它做到简单、可验证、不黑盒。

## 技术底座

- 同步引擎：[rclone](https://rclone.org) bisync（业界标准，自带冲突副本、删除安全阀、断点恢复）
- 面板：Go + 内嵌单页 Web UI，零外部依赖
- 挂载：rclone mount + WinFsp
- 针对 OpenList/国内网盘（天翼云等）实测校准：无哈希时退化为 size 比较、串行传输防 404、激进预取解决慢速上游
