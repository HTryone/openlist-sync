# 弱网调参指南

网络是这里的主要瓶颈。下面每个参数的作用、默认值和按带宽调节的建议。

## 1. 重试与超时（弱网核心）

| 参数 | 作用 | 默认（本方案） | 弱网建议 |
|---|---|---|---|
| `--retries` | 整个操作失败后的重试次数 | 10 | 极弱网可 15 |
| `--low-level-retries` | 单个 HTTP 请求级别的重试（连接抖动） | 20 | 丢包严重可 30 |
| `--contimeout` | 建立连接超时 | 30s | 高延迟可 60s |
| `--timeout` | 单次读写 IO 超时（大文件上传要够） | 5m | 大文件/慢速可 15m |
| `--transfers` | 并行传输文件数 | 4 | 弱网降到 2，减少争抢 |
| `--checkers` | 并行检查文件数 | 8 | 弱网降到 4 |

> 经验：**弱网优先降并发（transfers/checkers），加超时，再加重试**。并发太高会把
> 单条连接挤到超时，反而更慢。丢包环境先 `--transfers 2 --checkers 4`。

## 2. checksum 与性能

`--checksum` 按内容哈希判断变化，比 size+modtime 准，但：

- 需要 WebDAV 暴露哈希（OpenList 较新版本返回 `oc:checksums`）。
- 本地侧会实时算哈希，大目录会慢一点。

**自查是否原生支持哈希**：

```bash
rclone backend features openlist: | grep -i hash
# 或放个文件后：
rclone hashsum md5 openlist:/backup/workspace <file>   # 有输出=支持
```

若**不支持**哈希（输出空 / 报错），三选一：

1. 去掉 `--checksum`，用默认 size+modtime（最省事，但"改了内容却没改 mtime/size"会漏）
2. 加 `--no-slow-hash`：能算的一端仍算，不能算的一端用 size+modtime
3. 小文件很重要时用 `--download-hash`（下载整文件算 MD5，费流量，别对大目录用）

## 3. 安全阀（别关）

| 参数 | 作用 | 说明 |
|---|---|---|
| `--max-delete 50` | 单次删除超过 50% 文件即中止 | 防"列表失败被当成全删"。真要大删临时 `--max-delete 75` 或 `--force` |
| `--recover` | 中断后自动恢复，免 `--resync` | 弱网必开 |
| `--workdir` | 状态目录，放本地 | 默认在临时目录，显式指定更稳 |

## 4. 频率

- 每 **30~60 分钟**一次（弱网取 60，或夜间集中）。
- 失败不用慌：靠重试 + 下一次定时兜底。
- 不要高频（如 5 分钟）跑全量 bisync，弱网下会互相踩、浪费带宽。

## 5. 极端弱网：先用 fallback 单向

若 bisync 在实测里频繁卡在"中途中断→需 resync"，直接切
[备选方案](备选方案.md)：单向 `rclone sync` 备份 + `rclone copy` 预取共享目录。
每次都是幂等的，失败重跑无副作用，弱网容忍度更高。
